Flujo de Trading en Vivo

Cada vez que llega una nueva vela del WebSocket, el bot ejecuta este pipeline de 8 pasos. Haz clic en cada paso para ver más detalles.

1

📡 WebSocket Feed → CandleBuffer

Recibe velas OHLCV en tiempo real desde el exchange (Binance, Bybit, etc.)

El módulo data/websocket_feed.py mantiene un buffer circular de hasta 500 velas. Si el WebSocket falla, cae automáticamente a un modo REST de polling. Los datos llegan como [timestamp, open, high, low, close, volume].
2

🗓️ Filtro de Eventos Macro (EventsFilter)

Bloquea el trading 30 min antes / 15 min después de eventos de alto impacto.

Consulta ForexFactory (caché de 1 hora). Bloquea ante: FOMC, CPI, NFP, PIB, etc. Si el evento está dentro del período de blackout, devuelve (False, "Near CPI…") y el bot no abre ninguna posición. Protege de la volatilidad extrema post-noticia.
3

😱 Filtro de Sentimiento (SentimentGate)

Evalúa el Fear & Greed Index y las funding rates para decidir si operar.

Fear & Greed: Si el índice está por debajo de 20 (miedo extremo), bloquea longs. Si está por encima de 80 (codicia extrema), bloquea shorts.

Funding rates: Si la tasa de financiación es muy alta (>0.1%), el mercado está sobrecalentado en longs y se reduce la exposición.

Este filtro se refresca automáticamente cada hora.
4

📖 Filtro de Order Book (OrderBookFilter)

Analiza el desequilibrio bids/asks para confirmar la dirección de la señal.

Calcula el ratio: bids_vol / (bids_vol + asks_vol). Si hay más volumen de venta que compra frente a una señal long, la descarta. Threshold configurable (por defecto: 0.55 para long, 0.45 para short). Previene entrar contra la pared de órdenes institucionales.
5

🕯️ Patrones de Velas (CandlePatterns)

Confirma la señal con patrones de vela: martillo, engulfing, doji, etc.

Añade un candle_score entre -1 y +1 a cada barra. Un score positivo refuerza una señal de compra; negativo, de venta. Incluye: Hammer, Shooting Star, Bullish/Bearish Engulfing, Doji, Inside Bar, Three White Soldiers, Three Black Crows.
6

🔗 Filtro de Correlación (CorrelationFilter)

Evita abrir posiciones muy correladas entre sí para mantener diversificación.

Calcula la correlación de Pearson entre los retornos de la posición candidata y todas las posiciones abiertas. Si la correlación supera 0.80, rechaza la nueva entrada. Ejemplo: si tienes BTC abierto, no abrirá ETH si su correlación en las últimas 100 velas > 0.80.
7

🧠 Estrategia → Señal

La estrategia activa analiza los indicadores y genera una señal: +1 (buy), -1 (sell), 0 (hold).

Cada estrategia sigue el patrón:
prepare(df) → añade indicadores (EMA, RSI, ADX, ATR…)
generate_signals(df) → aplica la lógica y devuelve columnas signal, stop_loss, take_profit.

Se puede cambiar la estrategia activa en caliente por API REST o Telegram sin reiniciar el bot.
8

💰 RiskManager → Orden → Base de Datos → Telegram

Calcula el tamaño de posición, valida la orden y la registra inmediatamente en SQLite.

El RiskManager valida 4 condiciones antes de ejecutar:
1) Drawdown actual < límite máximo (15%)
2) Número de posiciones abiertas < límite (5)
3) Denominador de stop (entry − stop) > 1e-9 (stop no trivial)
4) Ratio R/R (risk/reward) ≥ mínimo configurado (2.0)

Si pasa, calcula el tamaño por ATR (atr_size()), comprueba el Portfolio Heat (máx 6% capital en riesgo total), y envía la orden. Todo queda persistido en SQLite inmediatamente, incluso en dry-run. Se notifica por Telegram.

Gestión de Riesgo — 6 Capas de Protección

El dinero se protege en cascada. Una posición tiene que pasar todos los filtros para abrirse. Haz clic en cada capa para entender los parámetros configurables.

1

Stop Loss ATR

Stop dinámico basado en volatilidad

El stop se coloca a 1.5× ATR (Average True Range) bajo la entrada para longs. El ATR mide la volatilidad reciente, por lo que el stop es proporcional al movimiento del mercado. Con ATR alto (mercado volátil) el stop es más amplio; con ATR bajo, más ajustado.

  • Fórmula long: stop = entry − ATR × 1.5
  • Fórmula short: stop = entry + ATR × 1.5
  • Configurable en config.yaml → risk.atr_multiplier
2

Tamaño de Posición Fijo

1% del capital por operación (por defecto)

Se arriesga un porcentaje fijo del capital en cada trade, independientemente del precio del activo.

  • Fórmula: size = (capital × stake_pct) / |entry − stop|
  • Default: stake_amount_pct = 0.01 (1% del capital)
  • Asegura que nunca se pierde más del 1% en una sola operación si el stop se respeta.
3

Kelly Criterion

Tamaño óptimo basado en historial de trades

Opcional. Se activa cuando hay al menos 30 trades en el historial.

  • Fórmula: kelly = (b × wr − (1 − wr)) / b, donde b = avg_win/avg_loss
  • Se usa Half-Kelly para mayor seguridad
  • Limitado entre 1% y max_position_size_pct (25% por defecto)
4

Portfolio Heat Manager

Máximo 6% del capital en riesgo total

Aunque el tamaño individual sea correcto, el calor total del portfolio no puede superar el 6%.

  • Heat = suma del riesgo en % de cada posición abierta
  • Si abrir una nueva posición llevaría el heat por encima del 6%, se bloquea
  • Protege ante eventos de correlación extrema (todas las posiciones caen a la vez)
5

Circuit Breaker de Drawdown

Pausa automática si DD > 15%

Si el capital cae más de un 15% desde su máximo histórico, el bot se pausa automáticamente.

  • drawdown = (peak_equity − current_equity) / peak_equity
  • La pausa se guarda en SQLite (bot_state[paused] = True)
  • Se puede reanudar manualmente por API o Telegram (/resume)
  • Configurable: risk.max_drawdown_pct
6

Filtro de Correlación

No abre posiciones con corr > 0.80

Antes de abrir una nueva posición, calcula la correlación de Pearson entre sus retornos y los de todas las posiciones abiertas.

  • Si correlación > 0.80 con cualquier posición existente → rechaza la entrada
  • Evita tener efectivamente la misma apuesta dos veces (ej: BTC y ETH muy correlados)
  • Usa los últimos 100 períodos para el cálculo
  • Threshold configurable: correlation.threshold = 0.80
Resumen: En el peor escenario (todas las posiciones van a stop al mismo tiempo), el bot nunca pierde más del 6% del capital en un día. El circuit-breaker para definitivamente si el drawdown acumulado supera el 15%.

Cómo Ejecutar Backtests Reales

# 1. Backtest rápido con datos de CCXT (Binance)
python main.py backtest --strategy supertrend --pair BTC/USDT --start 2022-01-01

# 2. Comparar todas las estrategias en el mismo dataset
python main.py compare --pair BTC/USDT --start 2021-01-01

# 3. Optimización Walk-Forward (más robusta que simple backtest)
python main.py optimize --strategy trend_ema --pair BTC/USDT --windows 5

# 4. Optimización bayesiana con Optuna (inteligente)
python main.py bayesian-optimize --strategy trend_ema --trials 200

# 5. Monte Carlo — ¿es el resultado estadísticamente sólido?
python main.py montecarlo --strategy supertrend --sims 1000

¿Qué es el Walk-Forward?

En lugar de optimizar sobre todos los datos históricos (overfitting), se divide en N ventanas. En cada ventana se entrena en el 70% y se testa en el 30% siguiente (datos nunca vistos). El resultado es mucho más realista que un backtest normal.

Ventana 1: [────TRAIN────|OOS] → métricas reales
Ventana 2:      [────TRAIN────|OOS] → métricas reales
Ventana 3:           [────TRAIN────|OOS] → métricas reales

Cómo Añadir una Nueva Estrategia

# 1. Crear el fichero
class MiEstrategia(BaseStrategy):
    name = "mi_estrategia"

    def generate_signals(self, df):
        df = df.copy()
        # ... tu lógica aquí
        df["signal"]      = 0   # 1=buy, -1=sell, 0=hold
        df["stop_loss"]   = df["close"] * 0.97
        df["take_profit"] = df["close"] * 1.06
        return df

# 2. Registrarla en strategies/__init__.py
STRATEGIES = {
    ...,
    "mi_estrategia": MiEstrategia,
}

# 3. Opcional: añadir espacio de parámetros en optuna_optimizer.py
PARAM_SPACES["mi_estrategia"] = lambda t: {
    "periodo": t.suggest_int("periodo", 10, 50)
}

# Ya está disponible en todos los comandos del CLI
Diseño limpio: todas las estrategias comparten el mismo BaseStrategy, el mismo RiskManager y el mismo engine de backtest. Añadir una nueva estrategia no requiere tocar el resto del sistema.
