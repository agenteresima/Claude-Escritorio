Configurar el archivo .env
Las variables de entorno controlan el comportamiento del bot
Requerido ▶

El archivo .env fue creado automáticamente por install.sh. Ábrelo con cualquier editor de texto:

Terminal
# Con nano (fácil para principiantes)
nano .env

# Con VS Code
code .env

# Con vim
vim .env

Para modo demo, la configuración mínima necesaria es:

.env — configuración demo mínima
# ── Modo papel (NO gasta dinero real) ──
DRY_RUN=true
EXCHANGE_SANDBOX=true

# ── Exchange (en sandbox no necesitas claves reales) ──
EXCHANGE_NAME=binance
EXCHANGE_API_KEY=tu_api_key_de_sandbox
EXCHANGE_API_SECRET=tu_api_secret_de_sandbox

# ── Estrategia activa ──
ACTIVE_STRATEGY=regime_adaptive

# ── Pares a operar ──
TRADING_PAIRS=BTC/USDT,ETH/USDT

# ── Riesgo conservador para empezar ──
STAKE_AMOUNT_PCT=0.02
MAX_OPEN_TRADES=3
MAX_DRAWDOWN_PCT=0.10

# ── API key (cambia esto) ──
API_KEY=mi_clave_secreta_aleatoria_32chars

# ── Telegram (opcional, deja vacío si no lo quieres) ──
TELEGRAM_BOT_TOKEN=
TELEGRAM_CHAT_ID=
✓
Con DRY_RUN=true y EXCHANGE_SANDBOX=true el bot nunca colocará órdenes reales. Puedes usar cualquier texto como API key para pruebas locales con datos históricos.
▶ Generador de API_KEY segura (haz clic)
5
Crear claves en el exchange (Sandbox)
API keys de prueba en Binance Testnet — dinero virtual
Opcional para backtest ▶
ℹ
Para backtesting y walk-forward no necesitas claves reales — el bot usa datos históricos descargados. Solo necesitas claves si quieres ejecutar el modo live paper trading con datos en tiempo real.

Opción A — Binance Testnet (recomendado)

PasoAcción
1 Ve a testnet.binance.vision e inicia sesión con tu cuenta de GitHub
2 En la sección API Keys, haz clic en Generate HMAC_SHA256 Key
3 Copia la API Key y el Secret Key — solo se muestran una vez
4 Pega ambas claves en tu archivo .env bajo EXCHANGE_API_KEY y EXCHANGE_API_SECRET
5 Verifica que EXCHANGE_SANDBOX=true esté en tu .env
Probar conexión al sandbox
source .venv/bin/activate
python -c "
import ccxt, os
from dotenv import load_dotenv
load_dotenv()
ex = ccxt.binance({
    'apiKey': os.getenv('EXCHANGE_API_KEY'),
    'secret': os.getenv('EXCHANGE_API_SECRET'),
    'sandbox': True,
    'enableRateLimit': True,
})
bal = ex.fetch_balance()
print('Conexión OK — USDT disponible:', bal['USDT']['free'])
"

El bot opera en tiempo real pero sin dinero real
Principal ▶
✓
En modo demo, el bot descarga velas reales del exchange, calcula señales reales y simula órdenes — pero nunca envía órdenes reales. Es como un simulador de trading en tiempo real.

Problemas comunes y soluciones
Errores frecuentes durante la instalación
Ayuda ▶
❌ ModuleNotFoundError: No module named 'ccxt'▶
El entorno virtual no está activado. Ejecuta:
source .venv/bin/activate
y verifica que el prompt muestre (.venv) al inicio.
❌ pip install falla con errores de compilación▶
Instala las herramientas de compilación:
Ubuntu/Debian: sudo apt install -y gcc g++ python3-dev
macOS: xcode-select --install
Luego vuelve a ejecutar bash install.sh.
❌ El bot no encuentra datos: EmptyDataError▶
El bot necesita descargar datos históricos la primera vez. Necesitas conexión a internet. Si usas un exchange sandbox, verifica que las claves sean correctas. También puedes usar datos sintéticos con:
python main.py sp500-backtest --no-download
❌ Address already in use: port 8000 o 8050▶
Otro proceso está usando ese puerto. Busca y cierra el proceso:
lsof -ti:8000 | xargs kill -9
lsof -ti:8050 | xargs kill -9
❌ Dashboard no carga en el navegador▶
Verifica que el proceso esté corriendo:
ps aux | grep dashboard
Si accedes desde otra máquina en la red, usa la IP local del servidor en lugar de localhost. También verifica que el firewall permita el puerto 8050.
❌ ccxt.NetworkError al conectar al exchange▶
El bot reintenta automáticamente hasta 4 veces con espera exponencial. Si persiste:
1. Verifica tu conexión a internet
2. Comprueba que EXCHANGE_SANDBOX=true apunta al endpoint correcto de testnet
3. Para desarrollo sin internet: usa --no-download en los comandos de backtest
❌ Telegram no envía mensajes▶
1. Verifica que TELEGRAM_BOT_TOKEN y TELEGRAM_CHAT_ID son correctos en el .env
2. Asegúrate de haber iniciado una conversación con tu bot en Telegram (envíale /start)
3. Prueba con: python -c "from bot.notifier import send_telegram; send_telegram('test')"
❌ Errores de permisos en Docker▶
Si ves Permission denied en Docker:
sudo usermod -aG docker $USER
newgrp docker
Y vuelve a intentar. En algunos sistemas puede ser necesario cerrar y volver a abrir la terminal.
💡 ¿Cómo ejecutar el bot al inicio del sistema automáticamente?▶
Usa systemd (Linux) o Docker con restart: unless-stopped. Ejemplo con systemd:
sudo nano /etc/systemd/system/tradingbot.service
Contenido:
[Unit]
Description=Trading Bot
After=network.target

[Service]
User=TU_USUARIO
WorkingDirectory=/ruta/a/Claude-Escritorio
ExecStart=/ruta/a/Claude-Escritorio/.venv/bin/python main.py live --dry-run
Restart=always

[Install]
WantedBy=multi-user.target
Luego: sudo systemctl enable tradingbot && sudo systemctl start tradingbot
